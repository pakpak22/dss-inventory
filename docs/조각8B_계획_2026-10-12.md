# 조각 8-B 계획 — [엑셀 기준 적용] (2026-10-12)

> **승인·구현 끝(2026-10-12).** 사용자가 `npm run db:migrate` 를 보내 승인(10절 다섯 가지 전부 추천안). 0008 적용, 코드·테스트·실제 치워 둔 파일로 끝까지 검증 완료. 아래는 계획 원문.

근거: DESIGN 6-6절(결정 2026-10-08 「2번 + 두 단추」), REQUIREMENTS 6절, `docs/엑셀_직접수정시_동작_2026-10-07.md`.
8-A 는 **보여 주기만** 했다. 8-B 는 치워 둔 파일(사람이 엑셀에 직접 적은 것)의 바뀐 줄을 **프로그램 기록으로 바꿔 원장에 쓴다.**
정본 원장에 쓰는 일이므로 **관리자 승인 관문**을 둔다. 자동으로 돌지 않는다 — 관리자가 두 번 눌러야 쓰인다.

---

## 1. 한눈에

```
치워 둔 파일 ──(8-A 비교)──> 바뀐 줄 ──(8-B 계획 세우기)──> ┌ 반영 가능: 기록 입력 N건 ┐
                                                           └ 반영 불가: 사람에게 남김  ┘
                                                                     │
                       관리자 ① [엑셀 기준 적용 준비] → 확인 화면(건별 내용·건수·사유 칸)
                       관리자 ② [원장에 적기]       → 한 트랜잭션: 원장 N건 + 적용 기록 + 멈춤 해제(써야 함)
                                                                     │
                                             다음 차례(1분)에 프로그램이 한 벌을 다시 쓴다
```

치워 둔 파일은 **지우지 않는다.** 실패하면 아무것도 안 쓰고(전부 되거나 전부 안 되거나) 멈춤 상태 그대로.

## 2. 무엇을 자동으로 바꾸나 — 줄 종류별

| 시트 | 차이 종류 | 처리 | 기록 종류 |
|---|---|---|---|
| 사용처 기입란 | **더한 줄** | 반영 | USE (수량 = 사용 재고, 날짜, 인수번호, 목적 및 출하담당 → 목적, 발주현황 → 유상/무상, 사용처, 비고) |
| 입고 기입란 | **더한 줄** | 반영 | RECEIVE (수량 = 입고) |
| 수량 변경 기록 | **더한 줄**, 종류가 조정·폐기·불량·대여 | 반영 | ADJUST / DISPOSE / LOAN(상대 = 빌려준 곳) |
| 수량 변경 기록 | 더한 줄, 종류가 반환·소유 옮김·기록 취소·처음 수량 | **사람에게 남김** | 되돌릴 원래 줄·상대 부품을 엑셀 글자로는 못 정한다 |
| 부품 재고 현황 | **수량 칸 바뀜** | 반영(마지막에, 3절) | ADJUST (차이만) |
| 부품 재고 현황 | 수량 아닌 칸 바뀜(비고·공급가·품명…) | **사람에게 남김** | 부품 정보 수정은 `/parts/No/edit` 에서 |
| 부품 재고 현황 | 새 No. / 사라진 No. | **사람에게 남김** | 부품 등록·삭제는 자동으로 안 한다 |
| 세 기록 시트 | **기존 줄 고침·지움** | **사람에게 남김** | 원장은 고치지 않는다(기록 취소로만) — DESIGN 6-6절 |

반영 불가 줄은 확인 화면에 **이유와 함께** 나열한다. 적용 뒤에도 멈춤이 풀리므로, 그 줄들은 사람이 평소 화면에서 적는다(8-A 안내와 같음).

## 3. 두 번 빼지 않게 — 부품 시트 수량은 마지막에 맞춤

엑셀에 수식이 없어서, 사람은 보통 **기입란에 줄을 더하고 부품 시트의 수량도 손으로 고친다.** 둘을 따로 반영하면 두 번 빠진다.

규칙: 기입란의 더한 줄을 먼저 반영한 뒤, 부품 시트의 바뀐 수량과 **그때의 프로그램 수량**을 견준다.
- 같으면 조정 안 함(엑셀의 수량은 더한 줄의 결과였던 것).
- 다르면 그 차이만 ADJUST(사유 「엑셀 기준 적용 — 치워 둔 파일 이름」).

확인 화면에는 부품별로 「엑셀 수량 X · 더한 줄 반영 뒤 예상 Y · 조정 ±Z」를 보인다.

## 4. 부품 맞추기 — 가져오기 규칙 재사용

기입란 줄에는 부품 No. 가 없다(No. 칸은 그 시트의 기록 번호). 품명·품명2·도번·소유 네 칸의 글자로 부품을 찾는다 — `src/lib/legacy/match.ts` 의 `buildPartIndex`·`matchRecord` 그대로.
- CONFIRMED(하나) → 그 부품.
- 16묶음(여럿)·소유 불일치·없음 → **사람에게 남김**(묶음 판정표는 과거 기록용이라 새 줄에는 안 쓴다).
- 날짜가 없거나 날짜로 못 읽는 줄, 수량이 0·숫자 아님 → 사람에게 남김.
- 인수번호가 `-`·빈칸이면 「수리 건 없음」 + 사유 = 사용처 글자. 인수번호가 있으면 USE 저장 때 서버가 다시 확인(통로 없으면 「확인 안 됨」으로 저장 — 지금 규칙 그대로).

## 5. 누가 적은 것으로 남나

- 원장의 **기록자 = 적용한 관리자**. 엑셀에 적힌 이름(「수리/정영빈」의 정영빈)은 사람 명단과 이을 수 없으므로 **비고에 남긴다**: 「엑셀 기준 적용 · 현황판_사람수정_20261012-1056.xlsx · 사용처 1654행 · 적은 이 정영빈」.
- 감사 로그 `WORKBOOK_EXCEL_APPLIED` 한 줄(치워 둔 파일 이름·지문·사유·쓴 기록 번호들·건수).

## 6. 멱등 — 같은 파일을 두 번 적지 않게

- 적용 기록 표 **`workbook_apply_logs`** 를 하나 둔다(append-only): 치워 둔 파일 이름·**sha256(UNIQUE)**·적용한 사람·시각·사유·쓴 기록 id 들·요약. 같은 지문이면 거절.
- 확인 화면은 계획의 **지문**(계획 JSON 의 해시)을 숨은 칸으로 들고 간다. [원장에 적기]를 누르면 서버가 치워 둔 파일을 다시 읽어 계획을 다시 세우고, 지문이 다르면 「내용이 바뀌었습니다. 다시 확인하십시오」로 거절.
- 두 관리자가 동시에 눌러도 한 번만: 조언 잠금(이미 쓰는 `dss-inventory:workbook-sync` 열쇠) + PARKED 인지 트랜잭션 안에서 다시 확인.

## 7. 한 트랜잭션

`recordEntry` 는 건마다 자기 트랜잭션을 연다. 8-B 는 **N건 + 적용 기록 + 멈춤 해제**를 한 트랜잭션에 넣어야 한다(중간에 모자라서 거절되면 앞 건만 쓰이는 일이 없게).
→ `ledger.ts` 에서 트랜잭션 안쪽을 `recordEntryIn(tx, …)` 으로 빼고 `recordEntry` 는 그것을 감싼다(동작 변화 없음, 기존 테스트로 확인). 8-B 는 `db().transaction` 하나 안에서 `recordEntryIn` 을 차례로 부른다.
실패하면 전부 되돌리고 어느 줄에서 왜 막혔는지 보인다(예: 「사용처 1654행 — No. 1 수량 부족(있음 3, 필요 5)」). 멈춤은 그대로.

## 8. 화면

- `/settings/workbook` 「사람이 손댄 내용」 구역에 단추 셋: **[프로그램 기준 적용]**(있음) · **[엑셀 기준 적용 준비]**(새로, 보조 단추) · [치워 둔 파일 내려받기](있음).
- `/settings/workbook/apply`(관리자): 반영 가능 N건 표(종류·날짜·부품 No.·품명·수량·엑셀 줄·비고에 들어갈 글자) + 부품 수량 맞춤 표(3절) + 반영 불가 M줄(이유) + **사유 칸(필수)** + 확인 체크 「위 N건을 원장에 적습니다. 되돌리려면 기록 취소를 건마다 해야 합니다」 + **[원장에 적기]**(위험 단추, 빨강). 반영 가능이 0건이면 단추 없음.
- 적용 뒤 `/settings/workbook` 으로 돌아와 「N건을 적었습니다. 다음 차례에 한 벌을 다시 씁니다」. 멈춤 띠는 사라진다.

## 10. 사용자가 정할 것 (추천을 앞에)

1. **부품 시트 수량 바뀜** — (가) 더한 줄 반영 뒤 차이만 조정(추천, 3절) / (나) 자동 반영 안 하고 사람에게 남김.
2. **수량 변경 기록의 반환·소유 옮김** — (가) 자동 반영 안 함(추천, 4절) / (나) 상대 글자가 부품 No. 꼴이면 소유 옮김만 시도.
3. **기록자** — (가) 적용한 관리자 + 엑셀 이름은 비고(추천, 5절) / (나) 다른 방식.
4. **실패 처리** — (가) 전부 되거나 전부 안 되거나(추천, 7절) / (나) 되는 것만 쓰고 나머지 남김.
5. **적용 기록 표 추가(마이그레이션 0008)** — 좋으면 때가 되면 `npm run db:migrate` 를 보내 주는 방식 그대로.

「계획대로」 한마디면 1~5 전부 추천안으로 착수한다.
