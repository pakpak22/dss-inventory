# 전환일 절차서 — 실자료를 넣고 현황판 엑셀을 프로그램으로 넘기는 날 (2026-10-12 작성)

> 누가 읽나: **담당자(최희만)** 가 NAS 에서 명령을 치고, **사용자(정영빈)** 가 숫자와 화면을 확인한다. Claude 는 배포·NAS 접속을 하지 않는다(CLAUDE.md 12-4절).
> 근거: DESIGN 5절(가져오기)·6절(엑셀 한 벌)·10절(승인 답변), REQUIREMENTS 6절, 2026-10-07 임시 DB `--real` 시험(CLAUDE.md 현황).
> 이 문서의 명령은 **개발 PC 에서 이미 돌려 본 것**이다. NAS 에서는 경로와 접속 정보만 다르다.

---

## 0. 한눈에

```
[전날]   현황판 최신 사본 받기 → --check-only 로 검사 → 양식 파일(틀) 두 벌이 그 현황판과 맞는지
[당일]   ① 엑셀 기입 중단 알림 ② 최종 사본 확정 ③ 빈 운영 DB 확인 ④ migrate ⑤ seed-items
         ⑥ import --real ⑦ 숫자 대조 ⑧ 앱 기동·로그인 ⑨ 첫 현황판 엑셀 생성 확인 ⑩ 옛 엑셀은 OLD 로, 새 위치 안내
[첫 주]  수기입 멈춤 처리법 공유, 백업 파일 생기는지, 쓸 사람 역할 등록
```

실패하면 ⑥ 은 **한 트랜잭션**이라 아무것도 들어가지 않는다. DB 를 비우고 다시 하면 된다(5절).

## 1. 전제 — 이것이 안 되어 있으면 시작하지 않는다

| # | 조건 | 누가 | 확인 방법 |
|---|---|---|---|
| 1 | **야간 백업**에 운영 DB 와 데이터 폴더(`INVENTORY_DATA_DIR`, 양식 파일 두 벌 포함)가 들어 있다 | 담당자 | 백업 목록에 둘이 보이는 화면 또는 말로 확인. **없으면 실자료를 넣지 않는다**(CLAUDE.md 2-0절) |
| 2 | 운영 포털 등록: 운영 주소 `https://inventory.dss21.co.kr`, redirect `…/api/auth/sso/callback`, 백채널 로그아웃 `…/api/auth/sso/backchannel-logout`, 운영용 `client_secret` 발급 | 담당자 | 환경변수 `SSO_*` 에 값이 들어 있다 |
| 3 | 운영 DB 가 **비어 있다**(표가 없거나, parts·stock_entries·legacy_records 가 0줄) | 담당자 | 3절 ③ |
| 4 | 데이터 폴더가 만들어져 있고 앱 컨테이너가 **읽고 쓸 수** 있다 | 담당자 | 2절 폴더 모양 |
| 5 | 환경변수 전부 채워짐(2절 표) | 담당자 | 앱을 띄우면 시작 때 빠진 것을 한꺼번에 알려 준다(`src/lib/env.ts`) |
| 6 | 현황판 최신 사본(사람이 마지막으로 적은 것)과 묶음 판정표 CSV 가 데이터 폴더 `import/` 에 있다 | 사용자 | 2절 |
| 7 | 쓸 사람 명단·역할(VIEWER/STAFF/ADMIN)을 포털에 등록 | 담당자 | 급하지 않음. 전환일에는 관리자(정영빈) 하나로도 된다 |

## 2. NAS 에 둘 것 — 폴더와 환경변수

### 2-1. 데이터 폴더 모양 (`INVENTORY_DATA_DIR`)

🔴 **개발 PC 의 `C:\DSS-INVENTORY-DATA\` 를 통째로 옮기지 않는다.** 넘기는 것은 **`templates/` 와 `import/` 둘**(프로그램의 입력)뿐이다. `workbook/`·`backup/`·`baseline/`·`현황판_사람수정_*.xlsx` 는 개발 PC 의 **데모 DB** 로 만든 결과물이라 가져가면 예시 부품 숫자가 든 엑셀이 NAS 에 「원본」으로 놓인다 — NAS 에서는 빈 폴더로 시작하고 전환일 ⑨ 에서 프로그램이 실자료로 새로 만든다. 넘길 묶음은 바탕화면 `재고관리 인계 (2026-10-12)\01 데이터 폴더\` 에 정리해 두었다(2026-10-12). 개발 PC 의 원래 폴더는 지우지 않는다.

```
<INVENTORY_DATA_DIR>/
  templates/
    재고 및 견적 현황판 틀_과거줄포함.xlsx   ← STOCK_WORKBOOK_TEMPLATE_PATH (현황판 엑셀을 만드는 양식. 과거 줄 2,314줄 값째 — 🔴 과거 자료 그 자체)
    재고 현황 내려받기 틀.xlsx                ← STOCK_DOWNLOAD_TEMPLATE_PATH
    재고 및 견적 현황판 틀.xlsx                (옛 틀, 참고용. 안 써도 된다)
  import/
    <현황판 최신 사본>.xlsx                    ← ⑥ 의 입력. 사람이 마지막으로 적은 것
    과거기록_묶음판정_2026-10-02.csv           ← --decisions
    (⑥ 이 만든) 못붙인_YYYY-MM-DD.csv          ← --unmatched 결과
  workbook/
    재고 및 견적 현황판.xlsx                   ← STOCK_WORKBOOK_PATH. 프로그램이 1분 주기로 통째로 다시 만든다. 사람들이 **보는** 파일
    OLD/                                      ← 월별 영구 백업(프로그램이 만든다)
  backup/                                     ← 일일 백업 30일(프로그램이 만든다)
  baseline/                                   ← 기준 파일(수기입 비교용, 프로그램이 만든다)
  현황판_사람수정_YYYYMMDD-HHMM.xlsx           ← 수기입 파일(멈췄을 때 프로그램이 치워 둔다. 지우지 않는다)
```

사람들이 엑셀을 **보는 자리**는 `workbook/재고 및 견적 현황판.xlsx` 하나다. 공유 폴더로 보이게 하고 그 경로를 `STOCK_WORKBOOK_SHARE_PATH` 에 적는다(화면의 [복사] 단추가 보여 주는 값).

### 2-2. 환경변수 (`.env.example` 의 이름 전부)

| 이름 | 운영 값(예) | 비고 |
|---|---|---|
| `DATABASE_URL` | `postgres://dss_inventory_app:<비밀번호>@<db호스트>:5432/dss_inventory` | 운영 DB. 개발은 5450 |
| `PORT` | `3800` | 컨테이너 안. 호스트는 `127.0.0.1:13800` |
| `AUTH_SESSION_SECRET` / `SSO_TX_SECRET` | 각 32자 이상, **서로 다른 값** | `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"` |
| `SESSION_COOKIE_SECURE` | `true` (HTTPS 뒤) | 리버스 프록시가 HTTPS 를 끊어 주면 true. HTTP 면 false 아니면 로그인이 조용히 실패 |
| `SESSION_HOURS` | `12` | |
| `SSO_ISSUER` | 운영 포털 주소(끝 슬래시 없음) | |
| `SSO_CLIENT_ID` | `dss-inventory` | |
| `SSO_CLIENT_SECRET` | 운영용(개발용과 다름) | 🔴 `NEXT_PUBLIC_` 금지. 메신저로 평문 전송 금지 |
| `SSO_REDIRECT_URI` | `https://inventory.dss21.co.kr/api/auth/sso/callback` | 포털 등록값과 글자 단위로 같아야 한다 |
| `AS_LOOKUP_URL` / `AS_LOOKUP_TOKEN` | A/S 인수번호 조회 통로(있으면) | 비면 「인수번호 확인 안 됨」으로 저장되고 나중에 [확인] |
| `INVENTORY_API_TOKEN` | 32자 이상(A/S 가 부품 API 를 쓸 때) | 비면 API 가 503, 화면은 영향 없음. **API 는 보류 중** |
| `INVENTORY_DATA_DIR` | `/data` (컨테이너 안 경로) | 위 폴더 |
| `STOCK_WORKBOOK_TEMPLATE_PATH` | `/data/templates/재고 및 견적 현황판 틀_과거줄포함.xlsx` | |
| `STOCK_DOWNLOAD_TEMPLATE_PATH` | `/data/templates/재고 현황 내려받기 틀.xlsx` | |
| `STOCK_WORKBOOK_PATH` | `/data/workbook/재고 및 견적 현황판.xlsx` | |
| `STOCK_WORKBOOK_SHARE_PATH` | `\\NAS\…\workbook\재고 및 견적 현황판.xlsx` (사람이 탐색기로 가는 경로) | 화면 표시 전용 |
| `DEV_ROLE_OVERRIDE` | 넣지 않음 | 운영에서는 무시된다 |
| `WORKBOOK_SYNC_DISABLED` | 넣지 않음 | `1` 이면 엑셀 자동 갱신이 꺼진다(점검용) |

경로는 전부 **컨테이너 안** 경로(`/`)다. 호스트 경로를 넣으면 컨테이너가 못 찾는다(CLAUDE.md 12-1절).

### 2-3. 이미지 둘

```bash
docker build --target runner -t dss-inventory:latest .     # 앱
docker build --target tools  -t dss-inventory:tools  .     # 마이그레이션·가져오기·자체 점검 (tsx 포함)
```

tools 이미지로 명령을 치는 모양(이 문서의 `[tools]` 는 전부 이것):

```bash
docker run --rm --env-file <운영 .env> -v <호스트 데이터 폴더>:/data dss-inventory:tools npx tsx scripts/<스크립트> <인자…>
```

> 2026-10-12 고침: tools 단계가 `src` 전체와 `tsconfig.json` 을 담도록 바꿨다. 그 전 이미지는 `migrate` 만 돌고 가져오기·자체 점검은 모듈을 못 찾는다. **이 PC 에서는 docker build 를 돌려 보지 못했다**(메모리) — NAS 에서 처음 빌드할 때 tools 로 `--check-only` 가 도는지부터 본다(3절 전날 ②).

## 3. 순서

### 전날

① **현황판 최신 사본**을 받아 `import/` 에 둔다. 사람이 마지막으로 적은 파일(지금 기준: `Desktop\2026.10.01 - 1. 재고 및 견적 현황판.xlsx` 계열, 세 시트, 수식 없음). 원본은 그대로 두고 **복사본**으로.

② **검사만** 돌린다(DB 에 아무것도 안 쓴다):

```bash
[tools] npx tsx scripts/import-workbook.ts --check-only "/data/import/<현황판>.xlsx" --decisions "/data/import/과거기록_묶음판정_2026-10-02.csv" --unmatched "/data/import/못붙인_검사.csv"
```

기대 출력(2026-10-07 시험값, 현황판이 그 뒤 바뀌었으면 달라진다): 부품 **319**, 사용 1,349 / 237 / 55 / 11, 입고 545 / 85 / 17 / 15, **못 붙인 26건**, 칸 사정 2건. 못 붙인 건수가 크게 늘었으면 현황판에 새 줄이 생긴 것 → `못붙인_검사.csv` 를 열어 보고, 필요하면 판정표에 줄을 더한다(이 결정은 사용자 몫. 묶음 판정표는 과거 기록용).

③ **양식 파일이 현황판과 맞는가.** 「재고 및 견적 현황판 틀_과거줄포함.xlsx」는 현황판의 사용처 1,652줄·입고 662줄을 **값째** 담고 있다. 현황판에 그 뒤 **과거 줄이 더 적혔으면**(전환일까지 사람이 엑셀에 계속 적었으므로 보통 그렇다) 양식을 다시 만든다:

```bash
[tools] npx tsx scripts/build-workbook-template.ts "/data/import/<현황판>.xlsx" "/data/templates/재고 및 견적 현황판 틀_과거줄포함.xlsx"
```

옛 양식은 이름을 바꿔 남긴다(지우지 않는다). 다시 만든 뒤 가져오기(⑥)와 **같은 현황판**에서 나온 것이어야 과거 줄 수가 맞는다.

④ 담당자: 운영 DB 비어 있음, 환경변수, 폴더 권한(앱 컨테이너 사용자 `nextjs`, uid 1001 이 `/data` 에 쓸 수 있어야 한다) 확인.

### 당일

① **엑셀 기입 중단을 알린다.** 이 시점 이후 엑셀에 적은 것은 프로그램에 다시 적어야 한다. 현황판 파일을 닫게 한다.

② **최종 사본 확정.** ①의 뒤에 현황판을 한 번 더 복사해 `import/` 의 파일을 바꾸고, 전날 ②·③을 그 파일로 다시 한 번(숫자가 같으면 넘어간다).

③ **빈 DB 확인**(담당자, psql):

```sql
select (select count(*) from information_schema.tables where table_schema='public') as tables;
-- 표가 이미 있으면:
select (select count(*) from parts) parts, (select count(*) from stock_entries) entries, (select count(*) from legacy_records) legacy;  -- 셋 다 0 이어야 한다
```

④ **마이그레이션**(0000~0008, 사용자 승인 뒤):

```bash
[tools] npx tsx scripts/migrate.ts
```

⑤ **항목 19종**(기준 자료, 몇 번 돌려도 같다):

```bash
[tools] npx tsx scripts/seed-items.ts
```

⑥ **실자료 가져오기**(🔴 한 번만. 빈 DB 가 아니면 스스로 거절한다. 전환일 날짜를 그날로):

```bash
[tools] npx tsx scripts/import-workbook.ts --real "/data/import/<현황판>.xlsx" --decisions "/data/import/과거기록_묶음판정_2026-10-02.csv" --unmatched "/data/import/못붙인_YYYY-MM-DD.csv" --transition-date YYYY-MM-DD
```

끝에 「넣음: 부품 N개, 처음 수량 줄 N개, 과거 기록 N건. 전환일 YYYY-MM-DD.」가 나온다. 중간에 멈추면 아무것도 안 들어간 것이다(한 트랜잭션) — 메시지를 읽고 고친 뒤 다시.

⑦ **숫자 대조**(담당자가 psql 로 뽑고 사용자가 ② 의 출력과 견준다):

```sql
select count(*) parts, min(no), max(no) from parts where is_deleted = false;                 -- 319, 1, 319 (시험값)
select sum(quantity) total, count(*) filter (where quantity = 0) zero from stock_balances;   -- 10,002 · 61 (시험값)
select count(*) opening_lines from stock_transactions t join stock_entries e on e.id = t.entry_id where e.type = 'OPENING';  -- 258 (시험값; 수량 0 부품은 줄 없음)
select match_status, count(*) from legacy_records group by 1 order by 1;                     -- CONFIRMED·GROUP_DECIDED·OWNER_MISMATCH 합 = 2,288 (시험값)
select value from app_settings where key = 'transition_date';                                -- 전환일
select action, actor_name, detail->>'file' from audit_logs where action = 'WORKBOOK_IMPORT';  -- 한 줄
```

`--check-only` 출력과 다르면 **여기서 멈추고** 5절로 되돌린다. 숫자가 맞으면 다음.

⑧ **앱 기동·로그인.** 앱 컨테이너를 띄우고 `https://inventory.dss21.co.kr` 로 들어가 카카오 로그인 → 정영빈이 **관리자**로 보이는지(머리말). 목록에 부품 319개, 아무 부품의 상세에서 「전환일(날짜) 이전 · 엑셀에서 가져온 과거 기록」 상자가 보이는지.

⑨ **첫 현황판 엑셀 생성.** 가져오기가 「써야 함」 표시를 남기므로 앱이 켜진 15초 뒤 첫 파일을 만든다. 바로 보고 싶으면:

```bash
[tools] npx tsx scripts/workbook-selftest.ts
```

네 파일(원본 `workbook/…xlsx`, 기준 `baseline/…`, 일일 `backup/…`, 월별 `workbook/OLD/…`)이 생기고 네 시트로 열리는지까지 스스로 확인한다. 그 뒤 **설정 > 엑셀 상태**: 상태 「정상」, 마지막으로 쓴 시각, 현재 파일 크기(KB), 백업 1개씩. 공유 폴더에서 그 엑셀을 열어 부품 재고 현황 319줄·사용처·입고 과거 줄·수량 변경 기록(처음 수량 줄)을 눈으로 본다.

⑩ **옛 엑셀 정리·안내.** 사람이 쓰던 현황판 파일은 `workbook/OLD/` 옆이나 별도 보관 폴더로 옮기고(지우지 않는다), 사람들에게 알린다:
- 보는 파일은 `<공유 경로>\workbook\재고 및 견적 현황판.xlsx` 하나. **읽기만.** 적는 일은 프로그램에서.
- 엑셀에 직접 적으면 1분 안에 프로그램이 알아채 「엑셀 수기입시 멈춤」이 되고, 관리자가 [프로그램 기준 적용] 또는 [엑셀 기준 적용]으로 풀어야 다시 갱신된다(`docs/엑셀_직접수정시_동작_2026-10-07.md`).
- 프로그램이 내려가 있을 때만 엑셀에 손으로 적고, 올라오면 관리자가 [엑셀 기준 적용]으로 옮긴다.

|---|---|---|

## 5. 되돌리기

- ⑥ 이 중간에 실패: 아무것도 안 들어갔다. 메시지대로 고친 뒤 다시 ⑥.
- ⑦ 숫자가 안 맞음: 담당자가 운영 DB 를 **비우고**(DB 를 지우고 다시 만드는 것이 가장 깨끗하다. 아직 사람이 적은 기록이 없는 시점이라 잃는 것이 없다) ④ 부터 다시. `--real` 은 빈 DB 가 아니면 거절하므로 반드시 비워야 한다.
- 양식 파일을 잘못 만듦: 옛 양식(이름 바꿔 둔 것)으로 되돌리고 앱의 다음 갱신을 기다린다. 양식은 **입력**이지 결과물이 아니라 DB 와 무관하다.
- 사람들이 이미 프로그램에 기록을 적은 뒤 문제를 알았다: 되돌리지 않는다. 원장은 append-only — 잘못된 건은 기록 취소로, 부품 정보는 부품 수정으로 고친다.

## 6. 담당자에게 보낼 요청 (초안 — 사용자가 다듬어 보냄)

> 최희만 님, 재고 관리(dss-inventory) 조각 1~8 이 끝나 실자료 전환 준비를 시작합니다. 아래를 부탁드립니다.
>
> 1. **야간 백업**에 재고 관리의 운영 DB 와 데이터 폴더(`INVENTORY_DATA_DIR`, 안에 엑셀 양식 두 벌 포함)를 넣어 주시고, 들어갔다는 확인을 주십시오. 이것이 확인되기 전에는 실자료를 넣지 않기로 했습니다.
> 2. **운영 환경변수 값**: 운영 포털 주소(`SSO_ISSUER`), 운영용 `client_secret`, 운영 DB 접속 문자열, 데이터 폴더의 컨테이너 안 경로와 사람이 탐색기로 가는 공유 폴더 경로. 이름 목록은 저장소 `.env.example` 에 있습니다. 시크릿은 메신저 말고 USB 나 직접 전달로 부탁드립니다.
> 3. **포털 등록**: 운영 주소 `https://inventory.dss21.co.kr`, redirect `/api/auth/sso/callback`, 백채널 로그아웃 `/api/auth/sso/backchannel-logout`. 역할은 등록된 그대로(VIEWER/STAFF/ADMIN).
> 4. 전환일 절차와 명령은 저장소 `docs/전환일_절차서_2026-10-12.md` 에 있습니다. Dockerfile 의 `tools` 이미지로 마이그레이션·가져오기·자체 점검을 돌리는 모양입니다. NAS 에서 처음 빌드하실 때 `--check-only` 가 도는지 먼저 봐 주시면 좋겠습니다.
> 5. 전환일에 넘길 것은 바탕화면 `재고관리 인계 (2026-10-12)` 폴더에 정리했습니다: 양식 두 벌·묶음 판정표·현황판 최신 사본(데이터 폴더의 `templates/`·`import/` 둘만, 결과물 폴더는 안 넘김), 절차서, 부품 319개 열쇠 목록. 엑셀 표 범위를 옮기는 함수(`src/lib/excel/stock-workbook.ts` 의 `retargetTable`)는 보여 드리기로 한 것이라 그때 같이 보겠습니다.
> 6. 쓸 사람 명단과 역할은 급하지 않습니다. 전환일에는 저(정영빈, ADMIN) 하나로 시작할 수 있습니다.
> 7. **코드 저장소**: `https://github.com/pakpak22/dss-inventory` (비공개). kiri190-me 계정에 쓰기 권한 초대를 보냈으니 수락해 주십시오. 서브모듈 `vendor/dss-ui` 가 있어 받을 때는 `git clone --recurse-submodules https://github.com/pakpak22/dss-inventory.git` 입니다.
> 8. 부품 No.·품명·도번은 재고 관리의 열쇠라 바꾸지 않습니다. 고객사 제출용 품명(견적서 등)은 A/S 쪽에 부품마다 수작업으로 두는 것으로 하고, 그 열쇠 목록을 함께 넘깁니다.
