🔴 결재자는 A/S 사람이라 명부를 열 때마다 받아 옵니다. 이름·역할은 그때의 사본을 함께 적어 두어 A/S 가 꺼져 있어도 저장된 절차가 그대로 보입니다.
🔴 「못 받아 왔다」와 「명부에 없다」를 가릅니다 — 꺼져 있을 때 「자격 없음」으로 그리면 멀쩡한 결재선이 깨진 것처럼 보입니다.

✅ 업무 결정 하나 끝 (2026-10-14) — 「남은 것 그만 주기(마감)」를 두기로 했습니다. 일부 나간 신청에만 뜨고 사유를 받습니다. 🔴 반려와 다릅니다 — 이미 나간 수량과 기록은 그대로 두고 남은 수량만 접습니다. 이력에도 「반출 반려」가 아니라 「반출 마감」으로 남습니다.
조각 4 설계에서 바로잡은 것 — 처음에 「줄 단위를 더해야 한다」고 적었는데 이미 있었습니다. 요청이 JSON 한 덩어리인 것은 저장 모양이고 그 안에 줄이 최대 50개 들어 있습니다. 원장도 이미 줄 단위입니다.
그래서 새로 만들 것은 부분 불출 하나뿐이고, 표도 하나만 더했습니다 (요청 줄 표는 안 만들었습니다 — 같은 사실이 두 곳에 적히면 어긋납니다).
조각 1 에서 알게 된 것 — 엑셀 변환 함수가 부품 타입을 통째로 받고 있었습니다. 값은 안 새지만 타입이 묶여 있어 칸을 더하자 바로 깨졌습니다. 받는 타입을 열두 칸으로 좁혀 고쳤고, 이제 「엑셀은 이 열두 칸만 받는다」가 타입으로 못 박혀 앞으로 칸이 늘어도 샐 길이 없습니다.
조각 2 에서 알게 된 것 — 이름이 겹칩니다
기록 내역에 이미 customer_name 이 있었습니다. 전혀 다른 것입니다.
출납 건의 customer_name 그 건의 고객사 이름 — A/S 에서 인수번호로 가져온 것
부품의 customer_name 고객사 품명 — 이번에 더한 것
주석 둘 · 시험 한 줄로 갈라 두었고, 화면의 「고객명」을 「고객사 이름」으로 바꿔 사람 눈에도 갈리게 했습니다.
이 일의 전제가 좋습니다. A/S 운영에 재고 자료가 한 줄도 없습니다 (부품 0 · 요청 0 · 원장 0 · O/H 템플릿 0 · 부품 연결된 견적서 줄 0). 그래서 「자료 이사」가 없고, 걷어내도 잃을 것이 없습니다.
