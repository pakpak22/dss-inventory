## 3. 가져오면 좋은 것 — 이번에 반영할 것

### 3-1. 원장 줄의 DB 제약을 A/S 수준으로 (🔴 마이그레이션 필요 → 사용자 승인)

A/S 는 `stock_transactions` 에 CHECK 가 일곱 개다. 특히 **종류에 맞는 부호**와 **되돌림 칸은 그 종류에만**. 우리는 `delta <> 0` 하나뿐이라 코드가 실수하면 DB 가 못 잡는다. 더할 것:

```
stock_transactions_delta_sign_matches_type :
  (type in USE,DISPOSE,LOAN → delta < 0) and (type in RECEIVE,RETURN,OPENING → delta > 0)
  (ADJUST·TRANSFER·CORRECTION 은 어느 쪽이든)
stock_transactions_returns_only_on_return   : returns_transaction_id is null or type = RETURN
stock_transactions_reverses_only_on_correction : reverses_transaction_id is null or type = CORRECTION
stock_entries_use_has_case_or_reason       : type <> USE or intake_number <> '' or (no_repair_case and reason <> '')
stock_entries_loan_has_counterparty        : type <> LOAN or counterparty <> ''
```

줄의 종류는 머리(`stock_entries.type`)에 있어 줄 표만으로는 CHECK 를 못 건다 → `stock_transactions` 에 `entry_type` 을 **복사**해 두고(머리와 같은 값, 쓰기는 ledger 한 곳) 거기에 CHECK 를 건다. A/S 가 줄마다 `transaction_type` 을 두는 것과 같은 모양이 된다.

### 3-2. 동시 수정 감지(`version` / `expectedVersion`) — 부품 수정에만

A/S 는 부품·잔량 행에 `version` 을 두고, 화면이 본 값과 다르면 「다른 사용자가 먼저 변경했습니다」로 거절한다. 수량 쪽은 우리가 `FOR UPDATE` 로 잠그고 **그 시점 수량**으로 다시 계산하므로 잘못되지는 않는다(화면의 "저장 뒤 N개" 미리보기만 어긋날 수 있다). 부품 **수정**은 두 사람이 같은 부품을 고치면 뒤의 저장이 앞을 덮는다 → `updated_at` 을 숨은 칸으로 보내 달라졌으면 거절. 작은 일이고 표 변경이 없다.

### 3-3. 이력 있는 부품은 삭제 단추를 아예 끈다

A/S 는 `hasLedgerHistory` 를 목록에 실어 체크박스를 비활성한다("고를 수 있게 해 놓고 나중에 거절하는 것은 왜 안 되는지를 한 번 더 눌러 봐야 알게 만드는 일"). 우리는 서버만 막는다 → 수정 화면에 「기록이 있어 지울 수 없습니다」를 미리 보이고 단추를 끈다.

### 3-4. 저장 뒤 제자리에 남기 (나중, 사용자 결정)

A/S 는 2026-09-17 사용자 요청으로 **저장 후 넘어가지 않고 팝업만 띄우고 그 자리에 남는다**(`showSavePopup`, `router.refresh`). 우리는 저장 뒤 기록 내역으로 넘어간다. 같은 회사 사람들이 쓴 결정이라 따를 가치가 있지만, 반출 화면은 휴대폰에서 여러 줄을 적는 흐름이라 다를 수 있다 → 조각 4 확인 때 사용자에게 묻는다.

## 4. 나중에 붙일 때 봐 둘 자리

- **요청 흐름을 옮길 때**: A/S 의 USE 줄은 `request_item_id`·`request_issue_id` 를 쌍으로 들고(CHECK 로 둘 다 있거나 둘 다 없음) 요청→불출을 잇는다. 우리 쪽은 `stock_entries` 에 `request_id` 한 칸이면 된다(한 건이 여러 줄이라 머리에). 상태 7종과 멱등 키 설계(`inventory-request-idempotency.ts`)는 그때 다시 읽는다.
- **O/H 템플릿(프리셋)**: `oh_part_templates` + `_items`(part_id null 허용, 이름만 담기) + `_models`(모델은 템플릿 하나에만). 프리셋 설계의 본보기.
- **고객 노출 품명·견적가 복사**: 단가 표가 "null = 정하지 않음, 0 = 무상" 을 가르는 규칙. 우리 견적가 null 도 같은 뜻으로 내주고 있다(API.md).
- **A/S 가 우리 부품을 읽어갈 때**: A/S 부품 고르개(`part-picker.tsx`)는 `id·partName·partSpec·drawingNo·kyosanPartNo` 다섯 칸만 받는다. 우리 API 의 `no·name·name2·drawingNo·kyosanPartNo` 와 1:1 이다.

## 5. 최희만에게 물을 것

1. `stock_transactions.resulting_quantity` 를 화면(거래 이력)에 「변경 후」로 보여 주는데, 바로잡기가 쌓이면 어긋나는 문제를 A/S 는 어떻게 다루나(A/S 엔 바로잡기가 없어 안 생기는 것인지).
2. 입고 창의 「위치」 자유 글자 — 현황판에는 위치가 없는데 A/S 는 왜 필수로 두었나. 우리가 위치를 안 두는 것이 맞는지 한 번 더 확인.
3. 저장 뒤 제자리에 남는 결정(2026-09-17)을 재고관리에도 적용할지.
